# GPT-6.1 Sol report and same-event quota recovery

The hosted `/report` page is protected by the existing private host capability. The host workspace links to it. It reports the current event's logged residents/messages/model decisions, recorded token usage and estimated USD usage, quota rejections, topic transitions, proposed information phylogeny, emerging conversational groups, and uncertainties. Source excerpts and message IDs accompany model claims. Proposed lineage and communities are interpretations; exact logged deliveries remain factual measurements.

`SemanticInsights` uses only GPT-6.1 Sol. A requested analysis has a $5 estimated API-equivalent allowance separate from resident networking wallets. It processes the full host-visible event and independent per-resident packets. Each resident packet is rechecked against sequence-based joined periods. Private host analysis never enters a resident's input or dashboard. Inputs include conversation excerpts (up to 1,500 characters), public names, delivery recipients and timestamps; private CVs, moral fields and personal memory notes are not added. Reports are observational and are not inserted into networking agent prompts.

Requests use the guarded, no-native-tools Hermes connection and fresh scoped sessions. Each response has attributable token/cost records. Unknown execution retains its reservation; explicit provider quota rejection releases the unused reservation. Failed requests never trigger a stronger model or keyword fallback. Validated source IDs cannot leave the allowed scope. Cached reports and persisted batch checkpoints avoid paying again for unchanged input. Reports and requests/responses are saved privately in the live state's `analysis/` and `analysis-audit/` directories. Reading a dashboard only reads cached data.

Host report refresh queues an explicit analysis command. The report page displays current analysis progress and spending. It never starts networking.

The dedicated gateway now preserves the original structured subscription-quota signal when Hermes' later retry guard message would otherwise hide it. Provider quota exhaustion stops all event workers, persists `paused_quota`, and retains the event ID, starting identities, conversation rooms, messages, memory, simulated day and usage. The host can confirm availability and choose **Resume existing event**. Resume continues the same event; no automatic quota poll, automatic restart or switch of model is performed. App restarts keep paused events paused. Individual USD allowances and voluntary wrap-up/end decisions remain in effect.

The initial event had 19 failures independently confirmed as `usage_limit_reached` in the provider log. A private SQLite/state backup was made before correcting their unused reservations to rejected and marking the existing event paused. The original 195 requests, 176 successful decisions, 252 messages, starting personas and conversation rooms were retained. No networking resume was performed to build the report.

Validation includes synthetic model and integration cases for quota pause/resume, event continuity, rejected reservations, cached analyses, source isolation, no networking Start, and actual Hermes adapter metadata propagation. Browser tests check the protected report, source evidence, model interpretation graph labels, private resident views and mobile layout.
